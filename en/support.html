Support – Parkeringsassistent P40

Information and contact options for Parkeringsassistent P40.

Independent app: Parkeringsassistent P40 is not developed, approved, supported or operated by SmartPark, Trondheim Parking, Trondheim Municipality or the parking operator.

What does the app do?

Parkeringsassistent P40 is a utility for users who already have access to the P40 parking scheme. It can help select a vehicle, display technical vehicle information, check an existing permit and show relevant parking status.

Privacy and security

Parkeringsassistent P40 is designed to minimize data sharing. The SmartPark session is stored in Apple Keychain, vehicle photos remain local, and Apple Watch does not receive the SmartPark token, phone number or SMS code. The app does not use advertising or cross-app/site tracking.

Sign-in problems

Check that the phone number used in Parkeringsassistent P40 is the same number registered with the existing SmartPark account. Sign-in is verified through SmartPark.

If the SmartPark session has expired, the app may show “P40 – sign-in required”. Choose “Open and sign in” to return to the sign-in flow.

Parking is not shown as active

Use “Check P40 status” in the app.

Parking status may be delayed or incomplete. Always verify in SmartPark that parking is actually registered and active.

Wrong vehicle

Check that the correct registration number is selected before starting a parking request. The registration number is the primary identifier for the vehicle to which parking applies.

Incorrect make, model or colour

Parkeringsassistent P40 may retrieve make, model and colour from the Norwegian Public Roads Administration API. These details are a practical aid and may occasionally be incomplete or differ from the vehicle's current appearance.

Vehicle photo

You may add an optional photo for each vehicle. The photo is stored only on the iPhone and is not sent to SmartPark, Cloudflare, the Norwegian Public Roads Administration or the developer.

Choose “Remove vehicle photo” to delete it. It is also deleted when the vehicle is removed from the app.

Apple Watch app and complication

The Apple Watch companion app shows P40 status, remaining time, registration number, vehicle and last verification time.

When the iPhone is reachable you can use Activate P40 or Check status from Apple Watch. The actual SmartPark check and any parking request are still performed on the iPhone.

If the iPhone cannot be reached, activation is deliberately not queued for later. This prevents an unexpected parking request from being attempted later.

SmartPark token, phone number and SMS code are not sent to Apple Watch.

On supported watch faces, P40 can also be added as a complication. The complication displays cached status received from the iPhone and is not a separate confirmation from SmartPark.

Language

Norwegian and English are built into the app and can be selected manually. The selected language is remembered until changed.

New users start in Norwegian when the iPhone language is Norwegian, English when it is English, and English for all other iPhone languages. Existing users are migrated to Norwegian when no previous language choice exists.

Additional on-device translated interface languages may be offered on supported Apple Intelligence devices. The language menu checks the actual English-to-target language pair on the current iPhone and only shows languages that Apple's Translation framework reports as supported or installed. Unsupported languages are hidden. Privacy, terms and support pages are maintained only in Norwegian and English; additional app languages open the English versions of these pages.

Automation

Open … → Set up / change automation for the recommended flow. The user selects the Automation vehicle, start time and weekdays in P40 and creates two core time automations in Apple Shortcuts: P40 Start and P40 Frigi. An optional/recommended P40 Ankomststart can also use Apple's Arrive trigger at 1 km around Sluppenvegen 17A to run Activate P40 as extra booking coverage.

P40 Start runs Activate P40. P40 creates a safety candidate only when that run actually creates a new P40 parking session near the configured start time on an enabled day. An already active parking session does not arm automatic release.

After a time-based booking, P40 handles arrival itself using a local, fixed 1 km safety zone around Sluppenvegen 17A. No separate Shortcut is required for this safety monitor. The optional P40 Ankomststart above is different: it is an extra booking trigger in Apple Shortcuts for evenings, weekends or later arrivals. P40's native 1 km zone is post-booking safety logic and never books parking by itself.

P40 Frigi runs Release P40 if not arrived no earlier than two hours after the actual booking. Before any automatic stop, P40 obtains a new, fresh location. GPS accuracy must also prove that the phone is safely outside the 1 km zone. Arrival monitoring must have remained trustworthy since booking, and the exact SmartPark parking session created by the automation must still be active. If GPS, arrival-monitoring continuity, network, sign-in or parking status is uncertain, parking is kept.

If Always location access has not been granted, P40 never stops parking automatically. The user receives a notification containing the booking time and the time the safety check ran, and is told to stop the session manually if the vehicle is not parked at P40.

Location is processed locally on the device. GPS coordinates are not sent to the parking service, the developer or the vehicle-lookup service and are not stored as parking history.

Live Activity and Lock Screen

Active P40 parking can be shown on the Lock Screen and Dynamic Island, including registration number, vehicle, start/end time, remaining time and last verified status.

“Last verified” shows when the app last received a successful status confirmation. If approximately 60 minutes pass without a new successful check, the Live Activity may say that status should be checked. This does not automatically mean the parking has expired.

Diagnostics and troubleshooting

P40 Health Check

The app provides a combined health check for SmartPark sign-in, SmartPark communication, P40 status, notifications, Live Activities, background refresh and Apple Watch when configured.

Choose “Test my system” to refresh the checks. When the user is signed in, the test may perform a read-only SmartPark status check. It does not start parking or change an existing parking session.

Session keep-alive and lifetime

Diagnostics shows when the current sign-in session was created. If the session already existed when this measurement feature was introduced, P40 instead shows when it first observed that session. The app also shows the last authenticated verification, last keep-alive, number of successful keep-alive runs and the live session lifetime.

When the parking service confirms that sign-in has expired, the end time and measured lifetime are frozen so keep-alive effectiveness can be evaluated. Manual sign-out is recorded separately and is not labelled as session expiry. The token, phone number and SMS code are not part of this measurement.

Recent events

The app can show a local timeline of recent diagnostic events. At most 30 events are stored for up to 7 days. The timeline is intended for troubleshooting and is not a parking history.

On supported devices, “What happened? Explain with AI” may use the Health Check and privacy-filtered event timeline to explain the sequence in plain language. The explanation is clearly labeled as AI-generated and identifies the model as Apple Foundation Models – SystemLanguageModel.default (on-device). iOS selects the exact system-model version.

On supported devices, choose “Explain diagnostics with AI” to use Apple Foundation Models – SystemLanguageModel.default (on-device) and generate an on-device, privacy-filtered explanation of what appears to have happened, written for a non-technical user.

The explanation is AI-generated. The recommendation about whether diagnostics should be sent to the developer comes from separate, deterministic P40 logic and is not generated by AI. AI can be wrong and does not determine whether parking is valid.

If sharing may be useful, open “See what is shared” before choosing “Send diagnostics to developer”. Registration numbers are masked and sign-in credentials are excluded. Nothing is sent automatically.

Open … → Diagnostics to view SmartPark session state, latest status check, background refresh, session keep-alive, status retry, notifications, Live Activity and Apple Watch connectivity.

Use Copy diagnostics if technical information needs to be shared with support. Known registration numbers are masked, and the report does not contain the SmartPark token, phone number, SMS code or other sign-in credentials.

Automatic P40 setup guide

The Home screen shows whether automation setup is ready. The guide checks sign-in, selected vehicle, Always location access, notifications and the two required time automations in Apple Shortcuts.

Apple does not give P40 access to read or modify the user's Personal Automation triggers directly. P40 can therefore show the exact values, open the named shortcut and record the user's confirmation, but the user must create or change the time trigger in Shortcuts.

The two core named shortcuts are P40 Start using Activate P40, and P40 Frigi using Release P40 if not arrived. In addition, P40 Ankomststart is recommended as an optional Arrive-trigger booking fallback and also runs Activate P40. P40's native 1 km arrival monitor is a separate post-booking safety mechanism and never starts parking.

On iOS 27 the guide follows Apple's current model: open the shortcut, choose Edit → Automation, use Time of Day, and enable Info → Privacy → Allow Running When Locked.

If the start time or weekdays are changed in P40, the relevant shortcut is marked as stale. P40 opens P40 Start or P40 Frigi for editing, shows the values to use, and asks the user to confirm the setup again. If the control time crosses midnight, P40 automatically shows the weekdays on which the control must actually run.

Shortcuts and status shows P40's local status: the last confirmed setup, last observed run and last recorded result. This is not a direct reading of Apple's Personal Automations list.
