If Parkeringsassistent P40 and SmartPark show different status, SmartPark's status must be treated as authoritative. If in doubt, check parking directly in SmartPark.

4. Third-party services and vehicle information

Parkeringsassistent P40 depends on external services. These services may change, be temporarily unavailable or return unexpected data.

The API provides technical vehicle information rather than owner information. Parkeringsassistent P40 does not request names, addresses or other owner details through this feature.

Vehicle information and an optional locally stored vehicle photo are practical aids only. The registration number and actual parking registration determine which vehicle the parking applies to.

Parkeringsassistent P40 relies on technical interfaces provided by the underlying parking service. These interfaces may change without notice, which may require app updates or cause some functions to stop working temporarily.

5. Parking requests

The app attempts to check existing parking status before requesting new P40 parking. The request is stopped if price, required fields or the parking-service response differ from what the app expects for the P40 flow.

An action in Parkeringsassistent P40 is not by itself confirmation that parking has been registered. The user must verify the actual registration in SmartPark. Parkeringsassistent P40 does not handle payment directly.

Stopping parking and automation

Parkeringsassistent P40 can stop an active P40 parking session when the user chooses Stop parking. Before sending the stop command, the app verifies the expected P40 product, the actually active vehicle and a short-lived active permit. A stop command is not blindly retried when the result is uncertain.

If the user enables Automatic P40, booking may be started by the time automation P40 Start, which uses the dedicated Start Automatic P40 action, and optionally by P40 Arrival Start using Apple's Arrive trigger. P40 Arrival Start uses its own dedicated action and requires a fresh on-device location check within 1 km before any booking. Manual Activate P40 is separate and can never arm automatic release. The selected start time is a hard lower boundary; P40 Start is never accepted before that time. After a relevant scheduled booking, P40 may monitor its own native fixed 1 km safety zone around Sluppenvegen 17A to record arrival evidence. This native zone never books parking. The app handles the automatic-release safety check itself; no separate “P40 Frigi” shortcut is required. P40 asks iOS for background execution no earlier than two hours after a new booking actually created by the time-based automation. iOS determines the actual background execution time, so the check may occur later than the two-hour threshold. P40 never stops parking before at least two hours have elapsed.

Immediately before any automatic stop, a fresh GPS location is processed locally on the device and active parking status is checked again. GPS accuracy must be sufficient to prove that the phone is safely outside the 1 km zone. Arrival monitoring must have remained trustworthy since booking, and automatic stopping requires the exact SmartPark parking session created by the automation to still be active. If GPS, arrival-monitoring continuity, network, sign-in or parking status is uncertain, the parking session is kept.

If the required location access has not been granted, P40 does not stop parking automatically. The user may be notified of the booking time and the time the safety check ran and must stop the parking session manually if the space is not being used.

Automatic stopping is a convenience feature and does not remove the user's responsibility to verify parking status when needed. SmartPark remains the authoritative place to check when status is uncertain or differs.

6. Live Activity, Dynamic Island, Lock Screen and Apple Watch

The app may display active parking information on the Lock Screen, Dynamic Island, Apple Watch Smart Stack and a supported watch-face complication. This may include registration number, vehicle information, start time, end time, remaining time and the time of the last verified status.

This is a convenient status display and must not be used as the only confirmation that parking remains active.

“Last verified” shows when Parkeringsassistent P40 last received a successful status confirmation. It is not a guarantee that parking is still valid or unchanged at a later time.

If the Live Activity or complication indicates that status should be checked, the information may be stale. This warning does not itself mean that parking has ended or become invalid.

Apple Watch actions: The companion app may ask the paired iPhone to activate P40 or check status. SmartPark checks and any parking request are still performed on the iPhone.

An activation request is deliberately not queued for later if the iPhone cannot be reached. An Apple Watch action is not confirmation that parking has been registered.
