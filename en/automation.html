Automatic P40 – setup and help

This page explains exactly what P40 handles automatically, what Apple requires you to configure in Shortcuts, and how to change the setup later.

In short: You create P40 Start with a time automation. You may also use P40 Ankomststart with an Arrive trigger at 1.5 km around Sluppenvegen 17A for extra booking coverage. P40 handles the two-hour safety follow-up itself; do not create a “P40 Frigi” shortcut.
Current start logic: The time selected in P40 is a hard lower boundary. P40 Start is never accepted before that time. If iOS delays the Time of Day automation, it may still run later on the same selected weekday. Manual Activate P40 is separate and can never arm the two-hour safety follow-up.

What does P40 do, and what do you do yourself?

P40 handles automatically

  • provides dedicated Shortcuts actions: Start Automatic P40 for P40 Start and P40 Arrival Start for the optional arrival automation
  • stores the start time and weekdays selected in P40
  • creates a safety candidate only when a scheduled run actually creates a new P40 parking session
  • monitors arrival within a fixed 1 km zone around Sluppenvegen 17A when Automatic P40 is enabled and Always location access is granted
  • performs a new, fresh location check before the safety follow-up can offer Release parking
  • keeps parking if location, sign-in, network or parking status is uncertain
  • shows local status for the last run and result

You configure in Shortcuts

  • the time automation that starts P40
  • optionally, P40 Arrival Start using an Arrive trigger at the recommended 1.5 km radius and the P40 Arrival Start action
  • you do not create a release automation; P40 handles the two-hour safety check
  • the same time and weekdays shown by P40
  • permission for the shortcuts to run while the phone is locked
  • updated time triggers if you later change the start time or weekdays in P40

Before you start

1

Sign in to Parkeringsassistent P40 and select the correct vehicle.

2

Open Set up / change automation in P40.

3

Select the start time and weekdays, then enable Automatic P40.

4

Grant P40 Always location access and allow notifications.

Important Shortcuts check: For both P40 Start and optional P40 Arrival Start, set Automation = on, Ask Before Running = off, Show When Run = off, Open When Run = off and Allow Running When Locked = on. P40 cannot read these Apple settings directly. The app therefore asks you to confirm them manually and shows actual observed runs separately. If P40 Start is not observed within 15 minutes after the scheduled start time on an enabled day, P40 shows a clear warning that the shortcut needs checking.

Step 1 – create “P40 Start”

Purpose: starts the parking request at your selected time.

  1. Select the vehicle you want to use on the P40 Home screen. The green vehicle is the default throughout the app and is used manually, by P40 Start and by P40 Arrival Start until you select another vehicle.
  2. In the P40 setup guide, tap Create in Shortcuts for Start P40.
  3. Find the P40 action Start Automatic P40 and use it in the P40 Start shortcut.
  4. Name the shortcut P40 Start.
  5. In Shortcuts choose Edit → Automation and add Time of Day.
  6. Check: open P40 Start and verify that its time trigger shows Automation = on, the correct time and weekdays are selected, and confirmation before running is disabled. Where iOS lists the shortcut is not used as proof that the trigger exists.
  7. Use the start time and weekdays shown by P40.
  8. Open Info → Privacy and enable Allow Running When Locked.
  9. Save, return to P40 and confirm that the setup matches.

Step 2 – recommended “P40 Ankomststart”

Purpose: extra booking coverage when you actually arrive at Sluppen, for example evenings, weekends or days you arrive later than usual.

  1. Create a new shortcut with the P40 action P40 Arrival Start. Verify that the action card itself says P40 Arrival Start; naming the automation P40 Arrival Start is not enough.
  2. Name it P40 Ankomststart.
  3. Choose Edit → Automation → Arrive.
  4. Use Sluppenvegen 17A with a 1.5 km radius.
  5. Turn Automation = on, turn Ask Before Running = off, and use the Arrive trigger's Time Range if you want to limit when arrival start can run. If you often pass through the area without parking, you can also omit this optional Shortcut.
  6. Enable Allow Running When Locked.
  7. Return to P40 and confirm the setup.

This Shortcuts geofence is an extra booking trigger. When iOS fires the Arrive trigger, P40 runs the dedicated P40 Arrival Start action and performs the normal status/duplicate checks without an additional 1 km GPS gate. P40's separate native 1 km zone is used only after a scheduled booking as safety evidence for the two-hour safety follow-up. Use Arrival Start only when entering the area normally means you intend to park at P40. “P40 Arrival Start” also checks for an existing active parking session before attempting a new one, so time start and arrival start can coexist without blindly creating duplicates.

Current setup health: Apple does not let P40 directly read the Personal Automation switch, Ask Before Running, or Allow Running When Locked. These settings must therefore be confirmed in the P40 guide. P40 can, however, record when its dedicated automation actions actually run. If a confirmed P40 Start has not been observed within 15 minutes after its scheduled time on an enabled day, P40 shows Check P40 Start with exact remediation steps. When notifications are allowed, P40 also schedules a local health reminder that is cancelled when P40 Start is actually observed.

Step 3 – P40's own native 1 km safety zone

After a relevant automatic booking, P40 arms its own native 1 km zone. This is not the same mechanism as the Shortcuts geofence above.

P40's native zone can never start parking. It records arrival evidence for the current scheduled booking and contributes to the later safety decision about whether an unused parking session can be released. The same fixed 1 km boundary is also used as a one-shot check when you manually tap I'M AT WORK. If a new manual parking session is created while the phone is safely outside the zone, P40 asks whether to Keep parking or Release parking. Manual parking is never released automatically.

Step 4 – built-in two-hour safety check

Do not create “P40 Frigi”. After a confirmed time-based pre-booking, P40 handles the safety check itself.

P40 asks iOS for background execution no earlier than 2 hours after the actual confirmed booking. iOS decides the actual background execution time and does not guarantee an exact start time. If delayed, P40 also retries through normal background status refresh and as soon as the app becomes active again. If iOS still hasn't provided a background opportunity shortly after the check becomes eligible, P40 shows a local time-sensitive reminder. Opening P40 then runs the same fail-safe check immediately.

P40 never offers Release parking before 2 hours have elapsed and never stops parking unless the user explicitly chooses it. All existing safety rules still apply: native 1 km arrival monitoring, fresh GPS, GPS accuracy, monitoring continuity, correct vehicle, exact SmartPark parking session and verified sign-in/status.

If you still have an old “P40 Frigi” shortcut or automation from an earlier test build, you can delete it. The current setup does not use it.

What happens at the two-hour safety check?

Arrival already recorded: parking is kept.
The phone is currently inside 1 km: arrival is recorded and parking is kept.
iOS has already reported that the phone entered the 1 km zone: P40 keeps parking even if an exact GPS verification was unavailable at that moment.
The phone is safely outside 1 km: P40 requires a fresh location and accounts for GPS accuracy. Release parking can only be offered when even the closest plausible position is outside the 1 km zone.
Arrival monitoring was interrupted: P40 does not release automatically. Monitoring must have been armed shortly after booking and remained trustworthy for the full interval.
The correct parking session: P40 verifies not only the vehicle but also the exact SmartPark parking session created by the automation. A newer parking session for the same vehicle cannot therefore be stopped by an older safety check.
The 1 km arrival monitor was not confirmed active: P40 does not release. You receive a notification with booking time and control time and can stop manually if the space is not being used.
The control ran too early: if P40 Start was delayed and 2 actual hours have not yet passed since booking, parking is kept. The notification shows booking time, control time and the earliest time a new safe check may run.
Always location access is missing: P40 does not release. You receive a notification containing both the booking time and the time the safety check ran.
GPS, network, sign-in or parking status is uncertain: P40 does not release.
Fail-safe: P40 prefers keeping a potentially unused parking session over stopping parking when the safety requirements cannot be verified.

Do you have an older setup with “P40 Ankomst”?

The older P40 Ankomst action recorded arrival and remains only for backward compatibility. Do not use it for a new setup. The new recommended P40 Ankomststart is different: it uses Apple's Arrive trigger and runs the dedicated P40 Arrival Start action so it can start booking.

When you change the start time or weekdays

  1. Change the value in P40.
  2. P40 marks whether P40 Start needs to be updated. “P40 Ankomststart” uses the recommended 1.5 km Arrive radius and normally does not change when times change. There is no P40 Frigi shortcut in the new setup.
  3. Tap Edit / verify in Shortcuts. P40 opens the named shortcut as far as Apple's supported URL integration allows.
  4. Choose Edit → Automation in Shortcuts and update the time trigger to the values shown by P40.
  5. Return to P40 and confirm the setup again.

Apple does not give third-party apps access to read or modify a Personal Automation trigger directly. P40 therefore cannot inspect Apple's automation list or silently change the trigger time in the background.

“Automation and status” in P40

The status screen shows P40's own knowledge: the setup you last confirmed, the last observed execution of the P40 action and the last recorded result. An observed run does not prove which Apple trigger launched it.

If location access is not granted

Automatic P40 may still have created parking through P40 Start. Without a safe location check, P40 does not offer “Release parking” in the two-hour safety follow-up. You are notified of the booking time and control time and told to check/stop the session manually if the space is not being used.

Privacy

Location is processed locally on the device after a scheduled automatic booking for arrival and safety checks around Sluppenvegen 17A. GPS coordinates are not sent to the parking service or the developer and are not stored as parking history. P40 stores limited local automation state, including the selected/default vehicle, booking time, vehicle registration number, the technical SmartPark identifier that binds the safety check to the correct parking session, arrival-monitoring continuity status, optional verified arrival time and the latest safety check.

Official Apple Shortcuts documentation

The setup above follows Apple's current Shortcuts model for iPhone. Apple may change the names or placement of controls in later iOS versions.
